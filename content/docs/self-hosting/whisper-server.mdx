title: Transcription server (WhisperX)
description: Run WhisperX on your own GPU for transcription, forced alignment, and speaker diarization — no cloud API.
---

Mesynx AI transcribes on **[WhisperX](https://github.com/etalab-ia/whisperx-openai-api)**,
which exposes the OpenAI-compatible `/v1/audio/transcriptions` endpoint plus
forced alignment and speaker diarization. It ships in the main
`docker-compose.yml`; use the standalone compose in
[`whisper-server/`](https://github.com/r0073d-l053r/mesynx/tree/main/whisper-server)
if you would rather run it on a **separate GPU box**.

> **Why a dedicated service.** Chat-only local servers like Ollama and Open
> WebUI do not implement the audio endpoint — they return `405 Method Not
> Allowed` on `/v1/audio/transcriptions`. WhisperX does, so it slots in as a
> normal Mesynx AI provider.

## Requirements

**A GPU is required.** There is no CPU image for WhisperX. You need an NVIDIA
card, current drivers, and the
[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).

You also need a Hugging Face token, because the diarization models are gated:

1. Create a free account at [huggingface.co](https://huggingface.co).
2. Accept the licence at
   [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).
3. Generate a **read**-scope token under **Settings → Access Tokens**.
4. Put it in `.env` as `HF_TOKEN=hf_...`.

Without a valid token the image fails on a gated-repo `401` at startup. Mesynx
AI's compose entrypoint catches this and idles with a clear message instead of
restarting forever, but it will not transcribe.

## Apply the model-alias patch

Run this once, before first start:

```bash
./patches/apply.sh
```

Mesynx AI signals diarization by appending `-diarize` to the model name, but
the stock WhisperX image rejects any model name that is not exactly its
configured one — so the documented convention returns **404** without this
patch. The script pulls the pristine file out of the published image, applies a
six-line diff, and writes the result for the bind mount. See
[`patches/README.md`](https://github.com/r0073d-l053r/mesynx/blob/main/patches/README.md).

The one-line installer does this for you.

## Start it

```bash
docker compose up -d

# Verify it is serving (this route needs no auth):
curl http://localhost:8398/health
```

First boot downloads the Whisper and pyannote models — one to two gigabytes —
so give it a few minutes. They are cached in the `whisperx_cache` volume and
survive restarts.

## Connect it to Mesynx AI

1. Open **Settings → AI Providers → Add Provider**.
2. **Provider:** `Custom (OpenAI-compatible)`.
3. **Nickname:** anything memorable, e.g. `Home GPU · WhisperX`.
4. **Base URL:**
   - `http://whisperx:8000/v1` if Mesynx AI runs in the *same* Compose network, or
   - `http://<gpu-host>:8398/v1` from another machine (a Tailscale IP works well).
5. **Test Connection**, then pick model **`large-v3-turbo-diarize`**, tick
   **Use for transcription**, and save.

Configure providers through the UI rather than writing to the database
directly — API keys are encrypted with a path that rejects plaintext, so a row
inserted by hand fails with `Could not decrypt the API key` on every request.

## Sizing `BATCH_SIZE`

The single biggest driver of GPU memory. Default is **4**.

| VRAM | `WHISPERX_BATCH_SIZE` |
| ---- | --------------------- |
| 8 GB | `4` |
| 12 GB | `8` |
| 16 GB+ | `16` |

Set too high, you get `CUDA failed with error out of memory` in the **whisperx**
logs — while the app shows only a bare `500` with nothing in its own log,
because the failure is upstream of it. When a transcription 500s with no
app-side log, check `docker logs mesynx-whisperx` and `nvidia-smi` first.

Uptime is a variable here. A long-lived CUDA process on a nearly-full card
fragments its allocator and creeps upward — one container grew from 2.6 GB to
6.5 GB over about 17 hours before failing mid-transcription.
`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` is set by default to counter
that, and a restart reclaims the rest.

## Other tunables

| Variable | Default | What it does |
| --- | --- | --- |
| `WHISPERX_MODEL` | `large-v3-turbo` | Base transcription model. |
| `WHISPERX_API_KEY` | `sk-placeholder` | Must match the key you enter in Settings. |
| `WHISPERX_ALIGN_LANGUAGES` | `["en"]` | Alignment models preloaded at boot. The image default preloads en/fr/nl/de (~4.1 GB resident); English-only is ~0.4 GB. Other languages still work — their alignment model loads on demand for the first request in that language. |
| `HF_TOKEN` | — | Required. See above. |

## Sharing a GPU with an LLM

If Ollama or another LLM server sits on the same machine, **pin them to
different cards**. An unpinned reservation lets a resident LLM and WhisperX
fight over the same GPU, which produces CUDA-OOM failures on exactly the
transcribe-then-summarise path the app runs on every recording.

Mesynx AI's compose pins WhisperX to device `0`. Point your LLM at another.

---

> **LLMs are not transcription models.** Gemma, Llama and GPT are *text*
> models — they cannot transcribe audio and will not answer
> `/v1/audio/transcriptions`. Use a Whisper-family model for transcription and
> configure an LLM separately as the **summary / enhancement** provider, where
> it cleans up and summarises the transcript.
